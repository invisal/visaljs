We could keep using `malloc`, but a garbage collector needs more control over where cells live. In this chapter, we build our own allocator.

JavaScript programs create many small cells, and throw most of them away almost as soon as they're made. Even a small function allocates several times.

```js
function label(user) {
  const name = user.first + " " + user.last; // strings
  const country = user.country.toUpperCase(); // a string
  const person = { name, country }; // an object
  return `${person.name} (${person.country})`; // a string
}
```

Once `label` returns, only the string it returns is still in use. Everything else it allocated is garbage, on every call. Freeing all of it leaves holes in memory, and holes lead to _fragmentation_, which we'll get to soon.

## Fragmentation

As the program keeps allocating and freeing, new cells reuse the holes old ones left, but they rarely fit exactly. Meanwhile, the cells that live longer stay where they are, between the holes. Over time, memory breaks up into used cells with free holes scattered among them. This is called *fragmentation*.

Fragmentation causes two problems.

- **Free memory we can't use.** There may be plenty of free memory in total, but split into holes too small for the cell we want. A tiny hole, like the selected one, may never fit anything at all.
- **Finding a hole takes time.** A simple allocator keeps a list of its holes, and on every allocation, searches it for one that's big enough. The more holes, the longer the search.

## Slab allocation

We're going to implement [slab allocation](https://en.wikipedia.org/wiki/Slab_allocation). A slab allocator takes memory in big pieces, and divides it by *size class*: one part of memory holds only 16-byte cells, another only 32-byte cells, and so on. When we ask for memory, the allocator looks at how much we need, finds the size class it falls into, and hands out a cell of that class.

Since every cell in a part has the same size, a hole left by a freed cell is exactly the size of the next cell of its class. No hole is ever too small.

We divide memory into 32 size classes, from 16 bytes up to 8 KiB. The heap keeps the memory of each class apart, in a list of its own.

```c
typedef struct {
    JSBlock *blocks[32];   /* one list per size class */
} JSHeap;

static JSHeap heap;
```

`heap.blocks[0]` holds all the 16-byte cells, `heap.blocks[1]` all the 32-byte cells, and so on, up to class 31. Each list is made of *blocks*, which we'll look at next.

| Class   | Cell size, in bytes            |
| ------- | ------------------------------ |
| 0 – 7   | 16, 32, 48, 64, 80, 96, 112, 128 |
| 8 – 11  | 160, 192, 224, 256             |
| 12 – 15 | 320, 384, 448, 512             |
| 16 – 19 | 640, 768, 896, 1024            |
| 20 – 23 | 1280, 1536, 1792, 2048         |
| 24 – 27 | 2560, 3072, 3584, 4096         |
| 28 – 31 | 5120, 6144, 7168, 8192         |

A size is rounded up to its class, so a 40-byte string gets a 48-byte cell. A little space at the end of a cell may go unused, but in return, every hole fits.

## Blocks

We take memory from the operating system in blocks of 64 KiB. The start of a block holds a small header, and the cells come after it, one after another.

The header says the size of the block's cells, and which of them are in use: one bit per cell, the *allocation bitmap*.

```c
typedef struct JSBlock {
    struct JSBlock *next;      /* the next block of its size class */
    uint32_t cell_size;
    uint32_t cell_count;
    uint8_t  size_class;
    uint64_t alloc_bits[64];   /* a bit per cell: in use */
} JSBlock;
```

A cell is at least 16 bytes, so a block has at most 4096 cells, and 64 words of bits cover them.

A new block comes from the operating system, with `mmap`. We place every block at an address that's a multiple of 64 KiB, and we'll see why that pays off in [Freeing](#freeing). `mmap` only promises a multiple of the page size, usually 4 KiB, so we map twice what we need, and give back the parts before and after the aligned 64 KiB.

```c
#define JS_BLOCK_SIZE ((size_t)64 * 1024)

static void *map_aligned(size_t size) {
    uintptr_t p = (uintptr_t)mmap(NULL, 2 * size, PROT_READ | PROT_WRITE,
                                  MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    uintptr_t start = (p + size - 1) & ~(size - 1);   /* round up to a multiple of size */
    if (start > p) munmap((void *)p, start - p);
    munmap((void *)(start + size), p + size - start);
    return (void *)start;
}

static JSBlock *new_block(unsigned size_class) {
    JSBlock *b = map_aligned(JS_BLOCK_SIZE);
    b->size_class = size_class;
    b->cell_size = js_size_class_bytes[size_class];   /* the table above */
    b->cell_count = (JS_BLOCK_SIZE - JS_BLOCK_FIRST_CELL) / b->cell_size;
    return b;
}
```

`JS_BLOCK_FIRST_CELL` is where the first cell starts: the size of the header, rounded up to 16 bytes. Memory from `mmap` is all zeros, so every allocation bit starts clear, and every cell starts free.

## Allocating

Now we replace `malloc` with our own allocator, `js_alloc`. It takes a size, just like `malloc`, so `js_new_string` from Strings changes by one line.

```c
JSValue js_new_string(const char *chars, uint32_t length) {
-     JSString *s = malloc(sizeof(JSString) + length);
+     JSString *s = js_alloc(sizeof(JSString) + length);
    s->cell.kind = JS_CELL_STRING;
    ...
}
```

Let's start with the simplest `js_alloc`. It finds the size class of the size, then walks the blocks of that class, cell by cell, until it finds a cell whose allocation bit is clear. If every block is full, it adds a new block from the operating system to the list, and looks again.

```c
void *js_alloc(size_t size) {
    unsigned size_class = js_size_class(size);
    JSCell *c = find_free_cell(size_class);
    if (!c) {
        add_block(size_class);   /* every block is full */
        c = find_free_cell(size_class);
    }
    return c;
}

static JSCell *find_free_cell(unsigned size_class) {
    for (JSBlock *b = heap.blocks[size_class]; b; b = b->next) {
        for (uint32_t i = 0; i < b->cell_count; i++) {
            if (!bit_get(b->alloc_bits, i)) {
                bit_set(b->alloc_bits, i);
                return block_cell(b, i);
            }
        }
    }
    return NULL;
}

static void add_block(unsigned size_class) {
    JSBlock *b = new_block(size_class);
    b->next = heap.blocks[size_class];   /* first in the list, so it's found first */
    heap.blocks[size_class] = b;
}
```

Since every cell in a block has the same size, cell `i` is at a fixed place, which `block_cell` works out.

```c
static inline JSCell *block_cell(JSBlock *b, uint32_t i) {
    return (JSCell *)((char *)b + JS_BLOCK_FIRST_CELL + i * b->cell_size);
}
```

## Faster allocation

Size classes fix *free memory we can't use*. But our `js_alloc` still has the other problem, *finding a hole takes time*. It starts from the first block every time, and checks one bit at a time. Once the first blocks are full, every allocation checks thousands of bits before it finds a free cell. That's much slower than `malloc`.

So each size class gets an *allocator*, which remembers where it left off. It works on 64 cells at a time: one word of the allocation bitmap, its *window*. It turns the free cells of that word into a mask, `free`, and remembers where the window's first cell is, `base`, which is `block_cell` of that cell.

```c
typedef struct {
    uint64_t  free;        /* a bit per free cell of the window */
    uintptr_t base;        /* the window's first cell */
    uintptr_t cell_size;
    JSBlock  *block;
} JSAllocator;
```

The heap keeps one allocator per size class, next to its lists of blocks.

```c
typedef struct {
+     JSAllocator alloc[32];   /* one per size class */
    JSBlock    *blocks[32];  /* one list per size class */
} JSHeap;
```

Now `js_alloc` doesn't search at all. It finds the size class of the size, and takes the lowest set bit of that class's mask.

```c
static inline void *take_cell(JSAllocator *a) {
    uint64_t free = a->free;
    a->free = free & (free - 1);                    /* clear the lowest bit */
    return (void *)(a->base + js_ctz64(free) * a->cell_size);
}

static inline void *js_alloc(size_t size) {
    unsigned size_class = js_size_class(size);
    JSAllocator *a = &heap.alloc[size_class];
    if (JS_LIKELY(a->free)) return take_cell(a);
    return js_alloc_slow(size_class);
}
```

`js_size_class` is a few bit operations, and when the size is a constant, the C compiler works it out at compile time. `js_ctz64` counts trailing zeros, which is a single instruction. So finding a free cell is two loads, a few arithmetic instructions and a store, and it's inlined into the caller. There's no function call and no search.

### The slow path

When the mask is empty, `js_alloc_slow` takes the next word of the block that has free cells, or another block of the class with room, or a new block from the operating system.

```c
void *js_alloc_slow(unsigned size_class) {
    JSAllocator *a = &heap.alloc[size_class];
    if (!next_window(a))                  /* the block's next word with free cells */
        use_block(a, find_block(size_class));
    return take_cell(a);
}
```

Taking a word sets all its free cells' allocation bits up front. The fast path hands cells out without touching the bitmap, so the bits have to say "in use" before it does. It also zeroes those cells. Zero bits are `JS_EMPTY` in [our NaN-boxing](/guide/jsvalue), so a cell that's only half filled in is still safe for the collector to look at.

## Freeing

Freeing a cell is just clearing its bit. But first, from the cell's address, we need its block and its index. Every block starts at an address that's a multiple of 64 KiB, so for any address inside it, clearing the low 16 bits gives the start of the block. And since every cell has the same size, the offset from there gives the index.

```c
static inline JSBlock *js_block_of(const void *p) {
    return (JSBlock *)((uintptr_t)p & ~(uintptr_t)(JS_BLOCK_SIZE - 1));
}

static inline uint32_t cell_index(JSBlock *b, const void *c) {
    return ((uintptr_t)c - (uintptr_t)b - JS_BLOCK_FIRST_CELL) / b->cell_size;
}

static void free_cell(JSCell *c) {
    JSBlock *b = js_block_of(c);
    bit_clear(b->alloc_bits, cell_index(b, c));
}
```

Nothing in a JavaScript program ever calls `free_cell`. Deciding which cells are garbage is the collector's job, and we'll get to it in [Mark and Sweep](/guide/mark-and-sweep).

## What's next?

Allocation is a few inlined instructions, holes always fit, and we know where every cell is: every set bit of every block's allocation bitmap. From any address, a mask finds its block, and a division finds its cell.
